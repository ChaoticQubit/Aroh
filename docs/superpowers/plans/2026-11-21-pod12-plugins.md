# Pod 12: Plugins

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A plugin is one TOML bundle per goal: tracker schemas, a view layout built only from the 24 approved component kinds and bound to those trackers, and optional personas and tool references. No plugin code. The server generates one per new goal, validates it with one repair round, stores and versions it; the app syncs it, renders the goal dashboard from it, falls back to the derived view when there is none, and lets the owner switch versions.

**Architecture:** `crates/aroh-plugins` (rewritten; the MVP YAML slot crate has no dependents) owns the bundle format: parsing, a strict validator whose errors name the file and the field, the binding vocabulary with each source's result type, version and enable rules over `aroh_domain::rows::Plugin` rows, the built-in templates, and one Rust table of every component kind and prop that a test renders to TypeScript and compares with `apps/aroh/src/lib/ui/contract.ts`. It emits the validated view tree as JSON with bindings intact. The app resolves bindings in `apps/aroh/src/lib/plugins/resolve.ts` against the loaded snapshot with the `views.ts` helpers, and the goal screen renders the resulting `ViewSpec` through `Render.svelte`, the only kind map. The server adds a `plugin-builder` persona, a `valid_plugin` eval (so troupekit's existing repair round fixes a bad bundle once), a `store_plugin` tool node after `write` in `new-goal`, and plugin endpoints. Plugin rows already sync through `aroh-store` (the `plugins` table is in `SYNCED`, SQLite and Postgres); one row is one version.

**Tech Stack:** Rust 2021, toml 1, serde_json, axum 0.8, utoipa 5; Svelte 5, TypeScript, vitest; Kiri; Xcode simulator tools.

## Decisions

| Topic | Decision | Reason |
|---|---|---|
| Crate | Rewrite `crates/aroh-plugins` in place: drop `serde_yaml`, `examples-yaml/`, the slot DSL; replace `docs/plugins.md`. Depends on `aroh-domain`, `serde`, `serde_json`, `toml = "1"`. | Q29: the YAML slot plugins are deleted once replaced; nothing depends on the crate. |
| Rows | One `plugins` row per version: `goal_id`, `name`, `version` (1, 2, ...), `bundle_toml`, `enabled`. A goal's active plugin is its enabled row with the highest version; none enabled means the derived view. Rows with no `goal_id` are the user's library. | The row already exists in every store; no schema change. A deterministic pick renders even when an enable flip is half synced. |
| Format version | `aroh_plugin = 1` inside the TOML. The row `version` is the revision; the bundle carries no revision of its own. | Two independent version axes, each in one place. |
| Bundle | Closed maps everywhere (unknown key is an error). Top level: `aroh_plugin`, `name` (slug, 2 to 40), `title`, `description?`, `tools?` (tool names), `[[trackers]]` (`name` unique, `[[trackers.fields]]` with `key`, `label`, `kind`, `unit?`, `choices?`, `target?` for number fields, `[trackers.cadence]?`), `[[personas]]` (`name` slug, `toml`), `[[sections]]` (`title` unique, `[[sections.items]]`). | Q16. Unique section titles because `GoalScreen` keys sections by title. |
| View items | An item is a table with `kind` and that kind's contract props. Each prop value is a literal of the contract type, or a binding `{ bind = "<source>", tracker?, field?, when?, limit? }` whose source result type equals the prop type (a nullable prop also takes the non-null type). `question_card.input` is a nested item, one level deep. | Renderer neutral (Q18): the tree is data shaped by the contract; bindings fill data props. |
| Binding sources | `series` (tracker, field: `Point[]`), `latest`, `today_total`, `change` (tracker, field: `number`), `target` (tracker, field with a declared `target`: `number`), `entries` (tracker: log entries), `streak` (tracker or none for actions: heatmap days), `actions` (`when` = `next`, `today` or `week`, `limit`: `ActionView[]`), `week_done`, `week_planned` (`number`), `week_start` (`string`), `deadline` (`string`). Field sources need a number field. | Covers today's dashboard (deadline, week ring, tracker lines, action streak, next actions) plus counters and stat tiles for other categories. |
| Empty data | A required value that resolves to nothing (no series points, no latest value, no deadline, no streak data, zero planned this week) drops its item; a section with no items is dropped; optional props are omitted. | Same rule `goalView` follows today. |
| Where bindings resolve | Rust validates every binding (source known, tracker declared, field declared and numeric, target declared, result type fits). Values are computed in TypeScript (`lib/plugins/resolve.ts`) from the snapshot with `views.ts` helpers, exported rather than copied. | Deviation from scope item 1's wording: action views, category slots and the deadline instant come from `actionViews`, `categoryViews` and `deadlineAt`, which other screens use; a Rust resolver would copy them (Q42). |
| Contract drift | `aroh_plugins::contract::KINDS` lists every kind with its props (name, optional, type). A test renders each kind and the named types (`Unit`, `CategorySlot`, `SeriesSlot`, `Ring`, `Point`, `ActionView`, `ChangeView`) to TypeScript text and compares them with `contract.ts` (`include_str!`, brace-aware parse, whitespace normalized), in order. | One source of truth (`contract.ts`); the Rust table fails the build on any drift. |
| Vocabulary drift | `resolve.ts` exports `SOURCES`; the Rust drift test parses that list and compares it with `aroh_plugins::bind::SOURCES`. An all-kinds fixture bundle uses every kind and every source; Rust asserts both coverages and pins its tree JSON; vitest resolves it and asserts all 24 kinds come out, no `bind` is left, and an unknown source throws. | Catches Rust and TS disagreeing on the vocabulary. |
| Untrusted bundles | Limits: bundle at most 64 KiB (`TOML_MAX`), 12 trackers, 20 fields per tracker, 8 personas, 12 sections, 24 items per section, 50 literal list items, text 1 to 200 chars (notes and persona text by their own caps). `photo_timeline.photos` and `capture` accept no literal URL source (photos only by binding, none exists yet). Persona TOML is checked with `troupekit_agent::Persona::parse` on the server. Tool names must be in a caller-supplied allowlist. | Q33 and the slice risk "agent-generated personas and plugins need strict schema validation". |
| Device validation | `commands/plugins.rs` runs the full validator on every synced row; an invalid row is listed with its error and never rendered, so the goal falls back. | Synced rows are checked only for length by `aroh-domain`. |
| Generation | `new-goal` gains `build_plugin` (agent, persona `plugin-builder`, reads `goal`, `plan`, `template`, writes `plugin_draft = {bundle_toml: string}`) and `store_plugin` (tool) after `write`, then `done`. `start_goal` puts the fitness template text in the run input as `template`. The persona has `evals = ["valid_plugin(bundle_toml)"]` and `max_turns = 2`, so troupekit's repair round runs once with the validator's errors. | The `[output]` DSL has no recursive types, so the bundle travels as a string. After `write`, a failed generation leaves a working goal on the derived view. |
| Q36 tradeoff | The dashboard is generated after plan approval, not shown for approval with the plan. | Keeps the approval loop and its tests unchanged; recorded as a deviation and an open item. |
| Store tool | `store_plugin` validates again, checks personas and tools, then writes the row with id `row_id(ctx, "plugin")` (replay safe), version = that row's version on replay else highest version of the goal and name plus 1, enabled; then disables the goal's other enabled rows; creates tracker rows for bundle trackers the goal lacks (matched by name); writes goal personas from the bundle. | Replay of a tool call must not mint a second version. Trackers are looked up by goal and name, not `trackers.plugin_id`, which would go stale on a version switch. |
| Endpoints | `GET /v1/goals/{goal_id}/plugins` (versions, newest first), `PUT /v1/goals/{goal_id}/plugins` (`{bundle_toml, enable?}`: validated, stored as the next version, 201; 422 names file and field), `GET /v1/plugins/{plugin_id}`, `POST /v1/plugins/{plugin_id}/enable`. | Brief: get, list, update (a new version, never an in-place edit) and enable. |
| Enable flips | Enable the target first, then disable the others. No transaction helper exists in `rows.rs`; the highest-version pick keeps every intermediate state renderable. | Avoids a moment with no enabled row. |
| App commands | `plugins_list(goal_id)`: rows of the goal, newest first, each with `tree` (validated JSON) or `error`. `plugins_enable(goal_id, plugin_id?)`: enables one version or, with none, disables all. `plugins_save(goal_id, bundle_toml)`: validates and stores the next version, enabled (owner edits). `plugins_use_template(goal_id, name)`: stores a built-in template as the next version. Each write emits `aroh://changed`. Device saves create missing trackers but leave bundle personas in the bundle: the app cannot run the persona parser, so only the server turns personas into rows. | Owner edits and reuses plugins (Q16); version switch works offline (Q35) and syncs. An unchecked persona row would break every later run's snapshot. |
| Version picker | `GoalScreen` takes optional `versions`, `version` and `onversion`; when there are versions it shows a "Dashboard" card with `Segmented` options "Derived" and `v1`, `v2`, ... Added to `/mockups`. | Approved card and segmented control, like the autonomy card. Deviation: a new use of approved components on an approved screen, listed for owner review. |
| Template | `crates/aroh-plugins/templates/fitness.toml`: countdown to the deadline, this week's ring, weight and protein lines, a 4-week action streak, next 4 planned actions. Equivalence test: vitest resolves the pinned fitness tree against a six-pack snapshot fixture and compares with `goalView` on the same fixture, countdown label excluded (date formatted by `goalView`). | Brief item 4 with proof. |
| Screenshots | Debug dev script on `aroh-p12`: seed the sample, store the fitness template as v1 for "Six pack by Feb 1", save a visibly different v2 through `plugins_save`, then capture v1, v2 after the switch, and "Learn piano" with no plugin (derived view). Files in `docs/screenshots/pod12/`. | A template equal to the fallback alone proves nothing. |
| e2e script | `e2e/script.py` gets a `plugin-builder` rule replying the fitness template; its rule count assert moves to 7. | The new node calls the model; the scripted loop must still reach `done`. |
